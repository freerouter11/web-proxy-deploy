# وب‌پروکسی شخصی — نسخه ۴٫۳ (کانفیگ‌های آماده گیت‌هاب)

یک **مرورگر پروکسی حرفه‌ای** با ظاهر و قابلیت‌های شبیه کروم: آدرس هر سایتی را بزن، از طریق سرور واسط باز می‌شود — حتی لینک‌هایی که با جاوااسکریپت ساخته می‌شوند. **پخش یوتیوب** هم با کیفیت قابل انتخاب پشتیبانی می‌شود.

## تازه‌های ۴٫۳ — کانفیگ‌های آماده (گیت‌هاب)

مخازن عمومی گیت‌هاب هر ۱۵ دقیقه کانفیگ‌های رایگان V2Ray (VLESS/VMess/Trojan/SS/Hysteria2) جمع می‌کنند؛ از داخل ایران گیت‌هاب‌راستی‌شده معمولاً فیلتر است — این بخش فهرست را **از طریق همین لایه‌ی پروکسی** می‌گیرد، تجزیه می‌کند و «نشانی اشتراک» آماده‌ی v2rayNG می‌سازد (v2rayNG هم می‌تواند همین نشانی را مستقیم مشترک شود — یعنی به‌روزرسانی خودکار کانفیگ‌ها بدون نیاز به VPN).

- مسیرها: صفحه `/configs` · فهرست منبع‌ها و کانفیگ‌ها `/api/configs?src=<id>` · اشتراک خام `/api/configs?src=<id>&raw=1` (اختیاری: `&n=20&random=1` برای زیرمجموعه‌ی سبک) · منبع دلخواه `/api/configs?url=<sub-url>`
- منابع منتخب (۶ عدد، همه تست‌زنده): 0xRadikal (تست‌شده/سریع + همه)، MatinGhanbari (همه + سوپر)، mahdibland، SoliSpirit
- تجزیه: متن خام یا base64 (تا دو لایه)، vmess (base64 JSON) / vless / trojan / ss (هر دو قالب) / hysteria2 / tuic / …
- امنیت و انصاف: محدودیت نرخ اختصاصی ۱۲ واکشی تازه در دقیقه برای هر IP + کش ۱۰ دقیقه‌ای؛ سقف حجم منبع ۴MB؛ فهرست ۵۰۰تایی در JSON؛ اشتراک خام تا ۱۲۰۰ کانفیگ
- ورودی‌ها: آیتم منوی پوسته «کانفیگ‌های آماده (گیت‌هاب)»، کاشی «کانفیگ‌ها» در تب جدید، و آیتم منوی ⋮ اپ اندروید ۴٫۳
- **صادقانه**: این کانفیگ‌ها عمومی و رایگان‌اند — کیفیت‌شان لحظه‌به‌لحظه فرق دارد و تضمینی نیست؛ خودِ اپ تونل VPN نمی‌زند و کانفیگ‌ها برای کلاینت‌های مخصوص (v2rayNG/Hiddify/NekoBox) هستند.
- اصلاح ۴٫۳: نقطه‌ی `/health` حالا **همیشه عمومی** است — اگر روزی `PROXY_PASSWORD` فعال شود، سلامت‌سنجی اپ و failover نمی‌شکند.

## مرورگر تصویری (ریموت) — از ۴٫۲

سرور آدرس را باز می‌کند، از صفحه **عکس** می‌گیرد و لینک‌هایش را **شماره‌گذاری** می‌کند؛ شماره را در کادر زیر عکس بزن تا همان لینک باز و عکسش بیاید — مثل کنترل از راه دور.

- مسیرها: صفحه `/remote` · فهرست لینک‌ها `/api/nav?url=` · عکس `/shot?url=&full=1`
- عکس‌ها را سرویس‌های رایگان می‌گیرند با زنجیره‌ی پشتیبان: mshots (وردپرس) → thum.io → microlink + کش ۱۰دقیقه‌ای (حافظه + کش edge کلودفلر)
- **صادقانه**: بار اول هر عکس ممکن است تا ~۲۰ ثانیه طول بکشد (دفعه‌ی بعد از کش فوری است)؛ سایت‌های لاگین‌دار یا ضدربات درست رندر نمی‌شوند؛ کلودفلر پلن رایگان خودش مرورگر ندارد و عکس را سرویس بیرونی می‌گیرد.
- کد مشترک در `remote.mjs` و `configs.mjs` — روی هر ۶ لایه (ورکرهای کلودفلر + Pages + Render) کار می‌کند.
- منبع اپ اندروید ۴٫۳ در `android-app/app/src/main/` (بدون androidx)؛ ساخت محلی با `TOOLS=/home/z/my-project/tools scripts/build-apk-local.sh` (خروجی ۴٫۳/versionCode 8).

## چه چیزهایی در ۳٫۱ محکم شد (بازبینی انتقادی)

- **محافظت SSRF کامل**: فرم‌های عددی IPv4 (مثل `http://2130706433` = 127.0.0.1)، هگز/اکتال، IPv6 نگاشته (`::ffff:127.0.0.1`)، ریدایرکت به آدرس داخلی و دامنه‌هایی که به IP خصوصی resolve می‌شوند — همه بلاک. (در نسخه‌ی Node، ورکر قبلاً اصلاً بررسی نداشت)
- **نشست جدا برای هر مرورگر**: کوکی‌های سایت مقصد دیگر بین همه‌ی کاربران مشترک نیست (کوکی `px_sid`). کوکی‌های `Domain=` هم روی زیردامنه‌ها کار می‌کنند.
- **ورکر کلودفلر هم جار کوکی دارد** (best-effort در هر isolate) — «ورود به سایت‌ها» روی لایه‌ی Cloudflare هم حالا کار می‌کند.
- **قفل Origin روی API تغییر IP**: سایت‌های دیگر نمی‌توانند حالت خروجی سرورت را عوض کنند (CORS باز حذف شد).
- **محدودیت نرخ درخواست** (۳۰۰/دقیقه برای هر IP، قابل تنظیم) + قفل تلاش‌های ورود (۸ در ۱۰ دقیقه).
- رفع باگ قطع‌شدن صفحات بزرگ‌تر از سقف بازنویسی، کش LRU واقعی، تشخیص charset از `<meta>`، پروکسی شخصی با احراز هویت (user:pass@host:port) + ماسک شدن رمز.
- **تست دودی ۲۹ موردی**: `node scripts/smoke.mjs` — امنیت، جدایی نشست‌ها، استریم و ورودی‌های خراب را هر بار چک کن.
- اپ اندروید: چند سرور ورودی با انتخاب خودکارِ سالم‌ترین، صفحه‌ی خطای فارسی، نوار پیشرفت.

## قابلیت‌های اصلی

- **رابط مرورگر کامل**: تب‌ها (با حالت ناشناس)، نوار آدرس هوشمند (جستجو یا آدرس)، دکمه‌های عقب/جلو/بارگیری مجدد، نشانک‌ها (★)، تاریخچه، جستجو در صفحه (Ctrl+F)، بزرگ‌نمایی (Ctrl ±/0) و میان‌برهای کیبورد مثل کروم
- **پخش یوتیوب**: جستجو، پلی‌لیست، انتخاب کیفیت (تا 1080p و بالاتر)، ادامه‌ی پخش از جای قطع‌شده — همه از طریق پروکسی
- **باز شدن همه‌ی لینک‌ها از مسیر پروکسی**: علاوه بر بازنویسی HTML/CSS، یک پچ هوشمند به صفحات تزریق می‌شود که `fetch`، `XMLHttpRequest`، `window.open`، `history.pushState` و لینک‌های داینامیک جاوااسکریپت را هم از مسیر پروکسی رد می‌کند
- **سوییچ سرور**: چند بک‌اند (ورکرهای مختلف، Render، سرور شخصی) تعریف کن، با یک کلیک بین‌شان جابه‌جا شو یا با «تست سرعت» سریع‌ترین را انتخاب کن
- **سرعت بالا**: کش چندلایه (کش edge کلودفلر + Cache API در ورکر / کش درون‌حافظه‌ای در Node)، انتقال جریانی فایل‌های بزرگ و فشرده‌سازی خودکار
- **رمز ورود اختیاری** و محافظت SSRF (در نسخه Node)
- **اپلیکیشن اندروید** با ساخت خودکار APK از GitHub Actions

> **مهم:** از این ابزار فقط برای مصارف شخصی و قانونی استفاده کن. برای کارهای حساس (بانک، پرداخت و…) مستقیم و بدون واسط به سایت وصل شو.

## ۱) نسخه‌ی همیشه‌آنلاین — Cloudflare Workers (بهترین گزینه)

**بدون هیچ ابزاری، فقط با کپی‌پیست:**

1. در [dash.cloudflare.com](https://dash.cloudflare.com) وارد شو → **Compute (Workers) → Create → Create Worker** → یک اسم بده (مثلاً `my-proxy`) → **Deploy**.
2. روی **Edit code** بزن، همه‌ی کد پیش‌فرض را پاک کن و **محتوای هر سه فایل** `worker.js`، `lib.mjs` و `assets.js` را به‌صورت سه ماژول جدا در ادیتور بساز (Add module) → **Deploy**.
3. رمز ورود (اختیاری): در صفحه‌ی Worker → **Settings → Variables → Add → نوع Plain text**:
   - Name: `PROXY_PASSWORD` — Value: رمز دلخواه (اگر تنظیم نشود، بدون رمز و باز است)
4. آدرس پروکسی تو: `https://اسم-ورکر.اسم-اکانت.workers.dev`

نکته: جار کوکی در نسخه‌ی Worker «best-effort» است (هر isolate حافظه‌ی خودش را دارد)؛ برای لاگین‌های حساس و پایدار، نسخه‌ی Node.js را فعال کن.

## ۲) اجرا روی کامپیوتر یا سرور خودت (Node.js)

پیش‌نیاز: [Node.js](https://nodejs.org) نسخه ۱۸ یا بالاتر.

```bash
node server.js            # پیش‌فرض روی پورت 3000
# یا:
PROXY_PASSWORD=رمز PORT=8080 node server.js
```

بعد در مرورگر باز کن: `http://localhost:3000`

فایل `.env.example` را به `.env` تغییر نام بده تا تنظیمات را همان‌جا بگذاری. برای روشن‌ماندن دائمی:

```bash
npm install -g pm2
pm2 start server.js --name web-proxy && pm2 save
```

## ۳) لایه‌ی ۴ — Render (Node.js کامل، رایگان، بدون کارت)

Render نسخه‌ی کامل Node را اجرا می‌کند (جار کوکی = لاگین به سایت‌ها، پخش یوتیوب، سرعت خوب) و **IP خروجی‌اش با کلودفلر متفاوت است** — یعنی لایه‌ای مستقل برای تغییر IP هم هست.

**استقرار (۵ دقیقه، بدون کارت اعتباری):**

1. در [render.com](https://render.com) با **GitHub** ثبت‌نام/وارد شو (Sign in with GitHub) — کارت نمی‌خواهد.
2. **New → Web Service** → در بخش Git، گزینه‌ی **Public Git Repository** را انتخاب و آدرس ریپوی عمومی را بچسبان:
   `https://github.com/freerouter11/web-proxy-deploy`
3. تنظیمات را این‌طور پر کن:
   - **Name:** `web-proxy`  •  **Language:** Node  •  **Region:** Frankfurt (نزدیک ایران)
   - **Build Command:** `npm install`
   - **Start Command:** `node server.js`
   - **Instance Type:** **Free**
4. **Create Web Service** را بزن؛ ۲ تا ۴ دقیقه بعد آدرس `https://web-proxy-xxxx.onrender.com` آماده است.
5. آدرس را در سوییچ سرورهای اپ اضافه کن (منوی ⋮ → تنظیمات → افزودن، یا لینک `?add-backend=Render|آدرس`).

> ⚠️ **محدودیت‌های پلن رایگان (صادقانه):**
> • بعد از **۱۵ دقیقه بی‌کاری می‌خوابد** و بیدار شدنش تا ~۱ دقیقه طول می‌کشد. تست سرعت اپ این حالت را می‌فهمد و «بیدار شدن…» نشان می‌دهد و خودش چند بار دوباره تلاش می‌کند؛ اولین باز شدن صفحه بعد از خواب کمی طول می‌کشد.
> • ماهانه ۷۵۰ ساعتِ روشن رایگان است (وقتی خوابیده باشد مصرف نمی‌شود) — برای استفاده‌ی شخصی کافی است.
> • رم ۵۱۲MB — سقف هیپ و کش سرور برای همین مقدار خودکار تنظیم می‌شود (`NODE_OPTIONS` و `CACHE_MB` در `render.yaml`).
> • اگر پهنای‌باند ماهانه تمام شود و کارت نباشد، سرویس تا اول ماه بعد متوقف می‌شود؛ مصرف شخصی معمولاً به آن‌جا نمی‌رسد.

## ۴) لایه‌ی ۵ — Back4App Containers (داکر، رایگان، بدون کارت)

لایه‌ی Node کامل روی کانتینر داکر، با **IP خروجی سوم** (متفاوت از کلودفلر و Render). پلن رایگان: ۰٫۲۵CPU، ۲۵۶MB رم، ۱۰۰GB پهنای‌باند، بدون کارت اعتباری.

> 💡 چرا Back4App به‌جای Koyeb؟ چون Koyeb از فوریه ۲۰۲۶ برای هر اکانتی **کارت اعتباری با پیش‌تراکنش ۲۹ دلاری** می‌خواهد — برای کارت ایرانی عملاً بسته است. Docker رایگان HF Spaces هم پولی شد. Back4App ساده‌ترین گزینه‌ی بدون‌کارتِ باقی‌مانده است.

**استقرار (۵ دقیقه):**

1. در [back4app.com](https://www.back4app.com) با **GitHub** ثبت‌نام کن (Sign up with GitHub) — بدون کارت.
2. در داشبورد: **Build new app → Containers** → **GitHub** را انتخاب کن و اپ Back4App را روی اکانت گیت‌هابت نصب/مجاز کن؛ ریپوی عمومی `freerouter11/web-proxy-deploy` را انتخاب کن (برنچ `main`).
3. Dockerfile ریپو خودکار پیدا می‌شود؛ نام اپ را `web-proxy` بگذار و Deploy را بزن.
4. بعد از استقرار، آدرس عمومی به شکل `https://web-proxy-xxxx.b4a.app` در صفحه‌ی اپ نمایش داده می‌شود.
5. آدرس را مثل قبل در سوییچ سرورها اضافه کن (`?add-backend=Back4App|آدرس`).

نکته‌ها:

- کانتینر روی پورت تزریق‌شده‌ی `PORT` گوش می‌دهد (خودکار؛ هیچ تنظیمی لازم نیست).
- رم ۲۵۶MB است؛ سقف هیپ (۱۹۲MB) و کش داخل Dockerfile تنظیم شده تا با OOM کرش نکند — اگر لاگ اجرا را ببینی، خط «کش: حداکثر …» مقدار خودکار را نشان می‌دهد.
- اگر روزی پلن پولی گرفتی، همان داکر روی Koyeb/Fly هم قابل استفاده است.

## ۵) Railway — آرشیو (ورک‌اسپیس محدود شد؛ دیگر توصیه نمی‌شود)

Railway نسخه‌ی کامل Node.js را با دامنه‌ی عمومی HTTPS اجرا می‌کند: جار کوکی (لاگین به سایت‌ها)، پخش یوتیوب و سرعت خوب — بدون هیچ تنظیمی. پلن آزمایشی هر اکانت ۳۰ روز رایگان است.

> 📌 **وضعیت فعلی (صادقانه و مستند):** ورک‌اسپیس فعلی محدود شده است. لاگِ استقرار ناموفق (۲۱ نوامبر) دقیقاً می‌گوید: «Suspicious activity: Your workspace has been restricted» — و مهم‌تر: Railway همان استقرار را با شناسه‌ی `cliCaller: agent_unknown:node` ثبت کرده است، یعنی **استقرارِ برنامه‌ای از طریق API را مثل عامل خودکار تشخیص داده و همین، عاملِ محدودیت بوده** — نه CLI و نه توکن. درسِ آموخته: با اکانت جدید هم **از خود داشبورد Railway مستقر شو (وصل‌کردن ریپوی GitHub در رابط وب)، نه با اسکریپت API**.

**اگر باز هم خواستی Railway را امتحان کنی — روش کم‌ریسک‌تر:**

1. با یک ایمیل جدید **از مرورگر** در railway.com ثبت‌نام کن و لینک تأیید ایمیل را باز کن.
2. در داشبورد Railway: **New Project → Deploy from GitHub repo** → ریپوی عمومی [`web-proxy-deploy`](https://github.com/freerouter11/web-proxy-deploy) را وصل کن — استقرار کامل از رابط وب، بدون هیچ اسکریپتی.
3. در تنظیمات سرویس دامنه‌ی عمومی بساز (**Settings → Networking → Generate Domain**).
4. آدرس را با لینک «افزودن به سوییچ» به ورکر اضافه کن.

> ⚠️ **ریسک‌های واقعی ثبت‌نام مجدد (بدون تعارف):**
> • Railway رسماً تأیید هویت را برای «جلوگیری از چنداکانتی» گذاشته؛ اکانت دوم را از راه گیت‌هاب، IP، اثر انگشت مرورگر و الگوی استقرارِ همان کد تشخیص می‌دهد.
> • **تله‌ی اصلی:** تریال کامل (شبکه‌ی باز — چیزی که پروکسی لازم دارد) فقط با تأیید «گیت‌هاب معتبر» فعال می‌شود. گیت‌هاب تازه‌ساخته = نامعتبر = تریال محدود (شبکه و پورت محدود) که پروکسی عملاً با آن کار نمی‌کند. گیت‌هاب قدیمی خودت را هم وصل نکن — اگر Railway علامت بزند، همان اکانت گیت‌هابی که کد و APK توست به خطر می‌افتد؛ این معامله‌ی بدی است.
> • اگر بگیرند: بدترین حالتِ واقع‌بینانه برای مصرف شخصی، محدود/بستن همان ورک‌اسپیس‌هاست (پیگیری حقوقی در این مقیاس عملاً صفر) — ولی انرژی و سرویسِ وسط کار از دست می‌رود.
> • **جایگزین بی‌ریسک و منطقی‌تر:** Render (بخش ۳) یا Koyeb را به‌عنوان لایه‌ی سوم بردار — هر پلتفرم IP خروجی متفاوتی دارد که همان چیزی است که برای تغییر IP می‌خواهی؛ چند پلتفرمِ مختلف، امن‌تر از چند اکانت در یک پلتفرم است. تغییر IP به‌علاوه از قبل داخل خود برنامه با استخر پروکسی/پروکسی دستی ممکن است و به هیچ اکانت جدیدی نیاز ندارد.

اسکریپت `railway-deploy.mjs` فقط برای حالتی نگه داشته شده که روزی استقرار API برایت باز باشد (مثلاً پلن پولی Hobby)؛ روی اکانت‌های تریال، استفاده‌اش همان محدودیتِ قبلی را تکرار می‌کند.

نکته‌ها:

- آدرس Railway با هر اکانت جدید عوض می‌شود؛ **ورودی همیشگی تو همان ورکر Cloudflare است** که همیشه آنلاین می‌ماند — داخلش بین لایه‌ها سوییچ کن.
- پلن آزمایشی علاوه بر زمان، سقف اعتبار هم دارد (۵ دلار)؛ مصرف سنگین ویدیو ممکن است زودتر تمامش کند.
- فایل `railway.json` تنظیمات دیپلوی (دستور اجرا + healthcheck) است.

## ۶) اپلیکیشن اندروید (نسخه‌ی ۳٫۲ — حرفه‌ای)

پوشه‌ی `android-app/` اپ اندروید بومی است که «مرورگر پروکسی» را با امکانات بومی اندروید اجرا می‌کند.

**دریافت APK:** ریپو → تب **Actions** → آخرین اجرای «Build Android APK» → بخش **Artifacts** یا تب **Releases**.

قابلیت‌های بومی نسخه‌ی ۳٫۲:

- **ویدیوی تمام‌صفحه** (دکمه‌ی fullscreen یوتیوب و همه‌ی سایت‌ها) + حالت Immersive + روشن‌ماندن صفحه هنگام پخش
- **آپلود فایل** به هر سایتی: انتخاب فایل یا عکس گرفتن با دوربین (کادر فارسی سه‌گزینه)
- **دانلود هوشمند**: کوکی نشست و User-Agent ارسال می‌شود ← دانلودهای نیازمند لاگین کار می‌کنند؛ نام فایل از هدر سرور (حتی نام فارسی) یا از URL داخلی؛ ذخیره در Downloads با نوتیفیکیشن خود سیستم
- **امنیت SSL**: گواهی نامعتبر هرگز نادیده گرفته نمی‌شود ← صفحه‌ی خطای فارسی
- **دیپ‌لینک**: لینک‌های سرور (از جمله «افزودن بک‌اند با یک کلیک») مستقیم در اپ باز می‌شوند
- **خروج امن**: اول تاریخچه، بعد «دو بار بزن برای خروج»
- **اسپلش** + **آیکون تطبیقی** مدرن (و تک‌رنگ/تم‌پذیر در اندروید ۱۳+)
- **نوار قطعی اینترنت** با تحمل جابه‌جایی وای‌فای↔داده
- **مدیریت کرش**: ثبت گزارش در `files/crash/` + پیام فارسی + اجرای دوباره‌ی خودکار
- **بازیابی از کرش رندر WebView** (موبایل‌های کم‌رم) بدون خروج از اپ
- لینک‌های خارجی (`tel:`، `mailto:`، `whatsapp:`، `intent://` و…) به اپ‌های خود اندروید می‌روند؛ `file://` بلاک است
- سرورهای ورودی به‌صورت **موازی** سلامت‌سنجی می‌شوند (نه پشت‌سرهم)

نکته‌ها:

- هر تغییری در `android-app/` بدهی و push کنی، APK جدید خودکار ساخته و منتشر می‌شود.
- فایل `keystore.jks` (رمز: `webproxy2024`) برای امضای APK داخل ریپو است تا نسخه‌های جدید روی قدیمی نصب شوند؛ اگر ریپو را عمومی کردی حتماً عوضش کن.
- «سرورهای ورودی» اپ (آرایه‌ی `HOMES` در `MainActivity.java`) فقط نقش ورودی/جانشین دارند؛ مدیریت بک‌اندهای پروکسی همان شل وب است (منوی ⋮). بعد از راه‌اندازی Render/Back4App می‌توانی آدرس‌شان را به `HOMES` هم اضافه کنی تا اگر ورکر اصلی فیلتر شد، اپ خودکار به ورودی بعدی برود.

## ۷) سوییچ بین سرورها (قابلیت سوییچ)

داخل مرورگر پروکسی، منوی **⋮ → تنظیمات و سرورها**:

- هر تعداد بک‌اند اضافه کن (ورکر دوم، Render، Back4App، localhost و…)
- **تست سرعت سرورها** زمان پاسخ هر کدام را می‌سنجد و سریع‌ترین را پیشنهاد می‌دهد؛ سرور خوابیده (پلن رایگان) را تشخیص می‌دهد، «بیدار شدن…» نشان می‌دهد و تا ۴ بار دوباره تلاش می‌کند
- با تغییر سرور فعال، صفحه‌ی فعلی از طریق سرور جدید بارگیری می‌شود
- با لینک `?add-backend=نام|آدرس` (مثلاً `?add-backend=Render|https://web-proxy-xxxx.onrender.com`) سرور جدید را با یک کلیک اضافه و فعال کن
- داده‌ها (نشانک/تاریخچه) روی هر سرور جدا ذخیره می‌شوند؛ با «دریافت/بازیابی داده‌ها» بین سرورها منتقلشان کن

چرا هم Cloudflare و هم Node؟ ورکر کلودفلر همیشه‌آنلاین و رایگان است (۱۰۰هزار درخواست در روز) و **ورودی اصلی و پایدار** توست؛ لایه‌های Node (Render لایه‌ی ۴، Back4App لایه‌ی ۵ یا سرور شخصی) جار کوکی دارند، برای لاگین به سایت‌ها و پخش یوتیوب کامل‌ترند و IP خروجی متفاوتی دارند — با سوییچر بین‌شان جابه‌جا شو. گیت‌هاب فقط میزبان کد و ساخت APK است (صفحات گیت‌هاب استاتیک‌اند و نمی‌توانند پروکسی باشند).

## نحوه‌ی کار

```
مرورگر تو  ←→  مرورگر پروکسی (شل)  ←→  سرور (Worker/Node)  ←→  سایت مقصد
```

1. آدرس را در نوار آدرس می‌زنی؛ اگر آدرس نیست، با موتور جستجوی انتخابی جستجو می‌شود.
2. صفحه از طریق سرور باز و همه‌ی آدرس‌های داخلش (لینک، عکس، CSS، فرم، fetch/AJAX) بازنویسی می‌شوند.
3. فایل‌های ایستا (عکس/فونت/اسکریپت) در کش چندلایه ذخیره می‌شوند → دفعه‌ی بعد چند برابر سریع‌تر.
4. یوتیوب به‌صورت اختصاصی از طریق API داخلی خودش پخش می‌شود (پلیر فارسی با انتخاب کیفیت).

**آدرس‌دهی مستقیم** (بدون شل) هم کار می‌کند:

```
https://آدرس-سرور/proxy?url=https://example.com
https://آدرس-سرور/https://example.com
https://آدرس-سرور/https://www.youtube.com/watch?v=VIDEO_ID
```

## متغیرهای تنظیم

| متغیر | توضیح | پیش‌فرض |
|---|---|---|
| `PROXY_PASSWORD` | رمز ورود؛ خالی = بدون رمز | خالی |
| `PORT` | پورت اجرا (نسخه Node) | 3000 |
| `ALLOW_PRIVATE` | اجازه‌ی آدرس‌های داخلی (نسخه Node، برای تست) | false |
| `PROXY_TIMEOUT_MS` | مهلت اتصال به مقصد | 30000 |
| `CACHE_MB` | سقف کش درون‌حافظه‌ای بر حسب مگابایت (خالی = خودکار بر اساس رم کانتینر) | خودکار |

## محدودیت‌ها و نکات

- یوتیوب برای بعضی ویدیوها (به‌خصوص موزیک‌ها) ممکن است موقتاً «تأیید ربات» بخواهد؛ این محدودیت سمت یوتیوب است و معمولاً بعد از مدتی رفع می‌شود — دکمه‌ی «تلاش مجدد» را بزن یا ویدیوی دیگری باز کن.
- سایت‌های خیلی سنگین از جاوااسکریپت (SPA ها) ممکن است کامل لود نشوند؛ هرچند پچ کلاینت حالا بخش بزرگی از درخواست‌های داینامیک را هم پوشش می‌دهد.
- وب‌سوکت (چت زنده و…) پشتیبانی نمی‌شود.
- در نسخه‌ی Worker کوکی‌های مقصد ذخیره نمی‌شوند؛ نسخه‌ی Node برای لاگین به سایت‌ها بهتر است.
- اگر پروکسی را عمومی اجرا می‌کنی **حتماً** `PROXY_PASSWORD` قوی بگذار.
- فایل `.env` حاوی رمز است و هرگز نباید به گیت برود (در `.gitignore` هست).

## سؤالات پرتکرار

**آدرس بدون `https://` زدم؟** خودش اضافه می‌شود. متن آزاد؟ با موتور جستجو جستجو می‌شود.

**فرم‌ها و لاگین‌ها؟** فرم‌های GET/POST کامل کار می‌کنند؛ در نسخه‌ی Node کوکی‌های مقصد هم نگه داشته می‌شوند.

**یوتیوب کیفیت بالاتر می‌خواهم؟** در صفحه‌ی پلیر، منوی «کیفیت» را باز کن؛ همه‌ی کیفیت‌های موجود ویدیو فهرست می‌شوند.

**سرعت را بیشتر کنم؟** چند ورکر در مناطق مختلف کلودفلر بساز و در تنظیمات اضافه‌شان کن؛ لایه‌های Render و Back4App را هم اضافه کن (لاگین و یوتیوب کامل‌تر + IP متفاوت). با تست سرعت همیشه سریع‌ترین را انتخاب کن.
